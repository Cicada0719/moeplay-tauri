# 萌游 (moeplay-tauri) 规则系统与观看体验修复 — 产品需求文档

| 项目 | 内容 |
|---|---|
| 仓库 | https://github.com/Cicada0719/moeplay-tauri |
| 模式 | 已有仓库改造，默认分支 `master` |
| 技术栈 | Tauri 2 + Svelte（保持不变） |
| 版本建议 | v1.x → v2.0（含数据迁移，建议升 minor/major） |
| 发布方式 | 推送 tag 触发 `release.yml` 自动构建 |

## 1. 背景与目标

### 1.1 背景

萌游是一款基于 Tauri 2 + Svelte 的桌面端聚合娱乐应用，覆盖番剧视频、漫画、小说三类内容，通过"规则（源）"机制聚合第三方站点。当前版本存在以下核心痛点：

1. **规则系统不稳定**：切换源后播放/解析频繁出错，用户体验不可预期。
2. **源大面积失效**：现有源多数已不可用，需要参考 animeko / kazumi 的成熟源配置方案重建源体系。
3. **播放器体验缺陷**：选择超清（4K）画质后控制栏无法自动隐藏。
4. **数据孤岛**：历史记录仅存储于本地，换设备即丢失。
5. **漫画/小说阅读体验不足**：历史功能简陋，漫画缺少双页（左右分屏）阅读模式。

### 1.2 目标

- 重建一个**可测试、可自愈、可扩展**的规则引擎，使源切换稳定、失败可降级。
- 交付一批**经自动化健康检查验证可用**的内置源（番剧/漫画/小说）。
- 修复播放器控制栏隐藏逻辑缺陷。
- 提供历史记录的**可选同步能力**（WebDAV / 服务端两种方案至少交付一种）。
- 优化漫画/小说历史记录功能，新增漫画双页阅读模式。

### 1.3 成功指标

| 指标 | 基线（现状） | 目标值 |
|---|---|---|
| 内置源健康检查通过率（每日 CI 探测） | < 30%（多数失效） | ≥ 80% |
| 源切换后首次播放成功率（手动测试抽样，每类源各 10 个条目） | 不稳定 | ≥ 90% |
| 源切换异常导致的崩溃/白屏次数 | 频发 | 0（全部降级为可恢复错误提示） |
| 超清画质下控制栏 3 秒自动隐藏成功率 | 0% | 100% |
| 历史记录同步端到端成功率（双设备验证） | 不支持 | ≥ 95%（冲突可解决） |
| 漫画双页模式渲染帧率（1080p，中等配置） | 不支持 | ≥ 50 FPS，翻页延迟 < 100ms |
| 旧版本历史数据迁移成功率 | — | 100%（含失败回滚） |

## 2. 用户故事

1. **作为**番剧观众，**我希望**在当前源失效或解析失败时能一键切换到其他源且播放器状态（集数、进度）不丢失，**以便**不中断地继续观看。
2. **作为**画质敏感用户，**我希望**选择超清画质后控制栏能像其他画质一样在几秒无操作后自动隐藏，**以便**获得无遮挡的沉浸式观看体验。
3. **作为**新用户，**我希望**应用内置的源开箱即用、并能看到哪些源当前可用，**以便**不用自己折腾配置就能找到能看的资源。
4. **作为**多设备用户，**我希望**我的观看历史能在台式机和笔记本之间同步，**以便**在任意设备上无缝续看。
5. **作为**漫画读者，**我希望**可以切换单页/双页（左右分屏）阅读模式，**以便**在宽屏显示器上获得接近实体书的阅读体验。
6. **作为**漫画/小说读者，**我希望**历史记录能精确记住我读到第几话/第几章、第几页/哪个位置，并能按最近阅读排序和搜索，**以便**快速回到上次的位置。
7. **作为**高级用户，**我希望**能导入/导出第三方规则文件（兼容 kazumi 风格的规则格式），**以便**自行扩展源而不必等待官方更新。

## 3. 功能需求

### 3.1 规则引擎重建与源切换修复

**FR-01 统一规则引擎（P0）**

重构规则（源）子系统，所有内容类型（番剧/漫画/小说）共用一套规则生命周期：加载 → 校验 → 执行（搜索/详情/章节/播放地址解析）→ 错误上报。规则执行在独立隔离环境中运行（前端沙箱或 Rust 侧 quickjs/boa 引擎），单条规则异常不得影响应用主体。

验收标准（Given/When/Then）：
- Given 一条语法错误的规则文件，When 应用加载规则，Then 该规则被标记为"无效"并在源列表中置灰，应用其余功能正常运行，日志中记录具体错误行信息。
- Given 一条规则在解析播放地址时抛出异常，When 用户点击播放，Then 界面展示"该源解析失败，建议切换源"的可操作提示（含"切换源"按钮），应用不崩溃、不白屏。
- Given 20 条规则同时加载，When 其中 5 条超时（>10s），Then 超时的 5 条被单独标记失败，其余 15 条正常可用。

**FR-02 源切换状态保持（P0）**

修复源切换 bug：切换源时必须保留当前内容的上下文（条目标识、集/话/章序号、播放进度），并在新源中自动定位到对应位置；若新源无该集数，则定位到最近可用集并提示用户。

验收标准：
- Given 用户在源 A 观看某番第 5 集、进度 12:30，When 切换到源 B 且源 B 存在第 5 集，Then 播放器加载源 B 第 5 集并从 12:30（±10s 容差）续播。
- Given 源 B 仅有 1~3 集，When 用户从源 A 第 5 集切换到源 B，Then 播放器定位到第 3 集并 Toast 提示"当前源暂无第 5 集，已跳转至最新一集"。
- Given 连续快速切换源 3 次，When 切换进行中，Then 仅最后一次切换生效（前序请求被取消，无竞态导致的串源播放）。

**FR-03 内置源重建（P0）**

参考 animeko（https://github.com/Animeko-org/Animeko）与 kazumi（https://github.com/Predidit/Kazumi）的源配置方式，重建内置源库：番剧源 ≥ 6 个、漫画源 ≥ 4 个、小说源 ≥ 3 个。规则格式采用与 kazumi 兼容或可直接移植的结构（JSON/YAML 描述 + 解析脚本），并为每条规则附带元数据（名称、语言、内容类型、版本、NSFW 标记）。

验收标准（清单式）：
- [ ] 内置番剧源 ≥ 6 个，且每日 CI 健康检查（真实搜索关键词"进击的巨人"或等价关键词）通过率 ≥ 80%。
- [ ] 内置漫画源 ≥ 4 个、小说源 ≥ 3 个，健康检查通过标准同上。
- [ ] 每条内置规则包含字段：`name, version, contentType, baseUrl, search, detail, chapter, parse`（或等价结构），缺字段的规则在加载时被拒绝。
- [ ] 全部内置规则存放在独立目录（如 `resources/rules/` 或远端拉取），与代码解耦，可在不发版的情况下通过规则热更新修复。

**FR-04 规则热更新与源健康状态展示（P1）**

应用启动时（及每 24 小时）从规则仓库拉取最新规则包（带版本号与签名校验），失败时回退使用本地缓存版本。源列表界面展示每个源的最近健康状态（可用/异常/未知）。

验收标准：
- Given 远端规则包版本高于本地，When 应用启动且网络可用，Then 规则静默更新并在设置页显示当前规则包版本与更新时间。
- Given 远端规则包签名校验失败或下载失败，When 应用启动，Then 使用本地缓存规则并记录警告日志，用户无感知中断。
- Given 某源最近 3 次健康检查均失败，When 用户打开源列表，Then 该源显示"异常"标识并自动沉底排序。

**FR-05 自定义规则导入/导出（P2）**

支持用户导入本地规则文件（兼容 kazumi 规则格式）及导出当前规则集合。

验收标准：
- [ ] 用户可通过"设置 → 规则管理 → 导入"选择本地 `.json/.yaml` 规则文件，合法规则出现在源列表，非法规则给出具体校验错误。
- [ ] 导入的自定义规则与内置规则在 UI 上可区分，且可单独删除。

### 3.2 播放器体验修复

**FR-06 超清画质控制栏自动隐藏修复（P0）**

修复选择超清（4K/超清）画质后底部控制栏不自动隐藏的 bug。根因排查方向：切换画质后原隐藏定时器/鼠标静止监听未重新绑定，或超清播放器的全屏容器重建导致事件监听器丢失。

验收标准（Given/When/Then）：
- Given 正在以超清画质全屏播放，When 鼠标静止 3 秒且无键盘操作，Then 控制栏与鼠标指针自动隐藏。
- Given 控制栏已隐藏，When 鼠标移动或按任意键，Then 控制栏在 200ms 内重新显示。
- Given 在超清与普清画质间来回切换 5 次，When 每次切换后鼠标静止 3 秒，Then 每次控制栏均能正常隐藏（回归验证原 bug 不复发）。
- Given 控制栏上有下拉菜单（选集/画质）处于展开状态，When 鼠标静止超时，Then 控制栏不隐藏，直至菜单关闭后重新计时。

**FR-07 播放器错误降级提示（P1）**

播放失败（网络错误、解析为空、403/防盗链）时展示结构化错误与建议操作（重试 / 切换源 / 复制日志），而非空白或卡死。

验收标准：
- [ ] 模拟播放地址返回 403，界面在 2 秒内显示错误类型与"切换源"按钮，点击后进入源切换流程且保留进度（联动 FR-02）。
- [ ] 连续重试 2 次失败后，自动弹出源推荐列表（按健康度排序）。

### 3.3 历史记录与同步

**FR-08 统一历史数据模型 v2 + 自动迁移（P0）**

统一番剧/漫画/小说三类历史记录的数据结构（见 §6 数据模型），并在首次启动时自动迁移旧版数据，迁移前自动备份。

验收标准：
- Given 存在 v1 旧版历史数据，When 升级后首次启动，Then 全部历史记录迁移至 v2 结构且条数一致，原始数据备份至 `backup/` 目录，迁移失败时回滚并提示用户。
- Given 一条漫画历史，Then 其包含字段：`contentId, contentType, title, cover, chapterId, chapterTitle, pageIndex, progress, sourceId, updatedAt, deviceId`。
- Given 迁移过程中应用被强制关闭，When 再次启动，Then 检测到未完成迁移并从中断点重试，不产生重复记录。

**FR-09 历史记录同步（P0）**

支持历史记录跨设备同步。首期交付 **WebDAV 同步**（用户自托管，如坚果云/Nextcloud），架构上预留服务端同步接口。同步策略：以 `updatedAt + deviceId` 做 last-write-wins 合并，冲突时保留进度更大的一方（可配置）。

验收标准（Given/When/Then）：
- Given 用户在设置中配置了合法的 WebDAV 地址与凭据，When 点击"立即同步"，Then 本地历史上传合并后拉取远端新增记录，并显示同步结果（上传 n 条 / 下载 m 条 / 冲突 k 条）。
- Given 设备 A 记录某番看到第 8 集（今天 10:00），设备 B 记录同番看到第 5 集（昨天 20:00），When 两台设备均执行同步，Then 两台设备最终均显示第 8 集进度。
- Given WebDAV 凭据错误，When 执行同步，Then 显示明确错误提示（认证失败），不清空本地任何数据。
- Given 同步过程中断网，When 网络恢复后再次同步，Then 数据最终一致，无重复记录（幂等）。
- [ ] 同步支持"仅手动"与"启动时自动 + 每 30 分钟"两种模式，默认为手动。

**FR-10 漫画/小说历史功能优化（P1）**

- 漫画历史精确到"第几话 + 第几页"，小说历史精确到"第几章 + 滚动百分比"。
- 历史列表支持按内容类型筛选（番剧/漫画/小说 Tab）、按最近更新排序、关键词搜索。
- 点击历史条目直接续读/续播到记录位置。
- 支持单条删除、按类型清空、批量删除。

验收标准：
- [ ] 用户阅读漫画至第 12 话第 7 页后退出，从历史列表点击该条目，直接恢复到第 12 话第 7 页（±0 页偏差）。
- [ ] 用户阅读小说至第 30 章滚动 45% 处退出，从历史进入后恢复至 45%（±5% 容差）。
- [ ] 历史列表输入标题关键词，200ms 内完成本地过滤并高亮匹配项。
- [ ] 删除单条历史后执行同步，其他设备上该条目同样被删除（墓碑标记机制）。

### 3.4 漫画双页阅读

**FR-11 漫画双页（左右分屏）阅读模式（P1）**

阅读器工具栏新增"单页 / 双页"切换按钮。双页模式下每屏显示两页，支持 LTR（左→右）与 RTL（右→左，日漫默认）两种翻页方向；单张跨页大图（宽度 > 高度 × 1.5）自动识别并独占整屏。

验收标准（Given/When/Then）：
- Given 用户在漫画阅读器，When 点击"双页"按钮，Then 当前屏显示两页且切换动画 < 300ms，模式选择被持久化（下次打开同一漫画仍为双页）。
- Given 双页 RTL 模式，When 用户点击屏幕右侧或按 → 键，Then 向后翻两页；点击左侧或 ← 键向前翻两页（RTL 下方向映射正确）。
- Given 下一页为跨页大图（宽高比 > 1.5），When 翻页，Then 该图独占一屏显示，页码计数仍正确（历史记录的页索引不漂移）。
- Given 窗口宽度 < 800px，When 切换双页，Then 提示"窗口过窄，建议单页阅读"，仍允许强制开启但图片自适应缩放不裁剪。
- Given 双页模式下退出再进入（联动 FR-10），Then 恢复位置时若页索引为奇数起始偏移，双页配对正确不串页。

## 4. 非功能需求

### 4.1 性能
- 应用冷启动 ≤ 3s（中等配置 Windows）；规则包加载（30 条规则）≤ 500ms，不阻塞首屏渲染。
- 源切换（FR-02）端到端耗时 ≤ 3s（不含目标源本身网络耗时），切换期间显示加载态。
- 漫画双页模式图片预取：当前屏 ±2 屏预加载，内存中缓存图片 ≤ 200MB，超出 LRU 淘汰。
- 历史记录列表 1 万条数据下滚动流畅（虚拟滚动），首屏渲染 ≤ 300ms。

### 4.2 安全
- WebDAV 凭据使用系统安全存储（Tauri 侧 keyring，如 `keyring` crate），**禁止明文写入配置文件**。
- 规则脚本在沙箱中执行：禁止访问本地文件系统与任意进程调用，网络请求经由统一代理层并记录审计日志。
- 规则包热更新需校验签名（ed25519）或至少 HTTPS + SHA-256 校验和，防止中间人注入恶意规则。
- 同步传输全程 HTTPS（WebDAV over TLS），证书校验不可关闭（或关闭时给出强警告）。

### 4.3 兼容性
- 平台：Windows 10/11 x64、macOS 12+（Intel/Apple Silicon）、主流 Linux 发行版（AppImage/deb），与现有 release.yml 产物保持一致。
- 旧版数据 100% 可迁移（FR-08），迁移失败自动回滚。
- 规则格式向后兼容：v2 引擎可加载为 v1 编写的规则（通过适配层），弃用字段给出警告而非报错。

## 5. 技术方案要点

### 5.1 总体架构（保持 Tauri 2 + Svelte）

| 模块 | 技术选型 | 理由 |
|---|---|---|
| 前端 UI | Svelte 4/5（沿用现有）+ 现有组件库 | 约束要求技术栈不变 |
| 播放器 | 沿用现有方案（预计 video.js / 原生 `<video>`），修复重点为**控制栏隐藏状态机重构**：统一用单一 store 管理 `idleTimer`，画质切换时通过 `onMount`/`destroy` 确保监听器重建 | 原 bug 根因大概率是切换画质重建播放器容器后旧定时器/事件监听悬空 |
| 规则脚本引擎 | Rust 侧引入 **boa_engine**（纯 Rust JS 引擎）或 **rquickjs**（QuickJS 绑定），推荐 **rquickjs** | boa 性能较弱；QuickJS 与 kazumi/animeko 的规则脚本习惯（JS 语法）兼容，移植成本最低；沙箱天然隔离 |
| 规则格式 | JSON/YAML 描述 + JS 解析函数，对齐 **kazumi 规则 schema**，编写一次性适配器转换 animeko 风格源 | kazumi 社区规则存量大，可直接复用；降低用户自定义门槛 |
| 网络层 | Rust 侧 `reqwest`（rustls）统一出口，注入规则脚本 | 便于统一超时、重试、UA、审计日志；规避 WebView CORS 问题 |
| 本地存储 | 沿用现有方案；若当前为 JSON 文件，建议迁移至 **SQLite（`rusqlite` 或 `sqlx`）** | 历史记录需支持筛选/搜索/墓碑删除/多端合并，SQLite 的事务与索引能力是同步功能的基础 |
| 同步 | WebDAV：Rust 侧自实现轻量 PROPFIND/PUT/GET 客户端（基于 reqwest）或引入 `webdav-handler` 的客户端部分 | 不引入重型依赖；协议简单可控 |
| 凭据存储 | `keyring` crate | 跨平台（Windows Credential Manager / macOS Keychain / Secret Service） |
| 漫画渲染 | 前端 `<canvas>` 或 CSS 布局 + 预取队列；双页配对逻辑放纯函数模块便于单测 | Svelte 响应式 + 虚拟化足够，无需 WebGL |

### 5.2 规则数据流

```
规则仓库 (git/远端 JSON 包, 带签名)
   ↓ 启动时拉取/校验 (FR-04)
本地规则缓存 (resources/rules/)
   ↓ 加载 & Schema 校验 (FR-01)
QuickJS 沙箱执行 (搜索/详情/解析)
   ↓ 统一 reqwest 网络出口
结果 → Svelte store → UI
```

### 5.3 历史数据模型 v2（SQLite 表示意）

```sql
CREATE TABLE history (
  id            TEXT PRIMARY KEY,        -- uuid
  content_id    TEXT NOT NULL,
  content_type  TEXT NOT NULL,           -- anime | manga | novel
  title         TEXT NOT NULL,
  cover         TEXT,
  source_id     TEXT NOT NULL,
  chapter_id    TEXT,
  chapter_title TEXT,
  page_index    INTEGER DEFAULT 0,       -- 漫画页 / 番剧集内位置
  position_sec  REAL DEFAULT 0,          -- 番剧播放秒数
  scroll_pct    REAL DEFAULT 0,          -- 小说滚动百分比
  updated_at    INTEGER NOT NULL,
  device_id     TEXT NOT NULL,
  deleted       INTEGER DEFAULT 0        -- 墓碑标记，同步用
);
CREATE INDEX idx_history_type_updated ON history(content_type, updated_at DESC);
```

### 5.4 关键实现注意点

- **FR-02 竞态处理**：源切换使用可取消的 async token（Rust `CancellationToken` / 前端 AbortController），新切换发起即取消旧任务。
- **FR-06**：控制栏隐藏逻辑收敛为单个 `useIdleTimer`（Svelte action），播放器组件 `onDestroy` 必须清理定时器；画质切换走"复用播放器实例 + 切换 source"而非销毁重建（若必须重建，则在 `onMount` 重新挂载 idle 监听）。
- **FR-09 合并算法**：按 `content_id + source_id` 匹配记录，`updated_at` 新者胜；同秒冲突取 `page_index/position_sec` 大者；删除通过墓碑记录传播，墓碑保留 90 天后清理。

## 9. 任务拆解建议

计划拆分为 **7 个子任务**（与里程碑对应）：

1. **规则引擎核心重构**：实现基于 rquickjs 的沙箱规则执行引擎与源切换状态保持/竞态取消（FR-01、02、05）。
2. **内置源重建与热更新**：参考 kazumi/animeko 重建 ≥13 个内置源，实现规则包拉取、校验与源健康检查 CI（FR-03、04）。
3. **播放器体验修复**：重构控制栏隐藏状态机修复超清不隐藏 bug，实现播放错误降级 UI（FR-06、07）。
4. **历史数据模型 v2 与迁移**：SQLite 化 + v1→v2 自动迁移、备份与回滚（FR-08）。
5. **历史同步（WebDAV）**：WebDAV 客户端、凭据安全存储、冲突合并与墓碑删除（FR-09）。
6. **漫画/小说历史优化与双页阅读**：历史精确续读、列表筛选搜索、漫画双页/RTL 模式（FR-10、11）。
7. **全量回归与发布**：三端回归测试、数据迁移演练、打 tag 走 release.yml 发布。

**依赖关系**：
- 任务 1 → 任务 2（源依赖引擎）；
- 任务 4 → 任务 5（同步依赖新数据模型）；
- 任务 3 与任务 1/2 独立，可并行；
- 任务 6 依赖任务 4（复用历史模型）但与任务 5 可并行；
- 任务 7 依赖全部前置任务完成。

建议执行顺序：**1 → (2 ∥ 3) → 4 → (5 ∥ 6) → 7**。
