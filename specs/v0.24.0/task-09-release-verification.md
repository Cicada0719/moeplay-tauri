# Task 09：发布前校验与 Android 升级证据

## 目标与依赖

依赖 Task 01–08。把错误产物挡在公开发布之前，升级声明必须绑定实际 APK 和测试证据。

## 允许修改

`scripts/` 发布/升级校验脚本、相关 CI 校验步骤、`update-server/deploy/activate.py` 和下载页声明。禁止重建另一套发布流程或删除既有版本。

## 行为

- 升级报告按输入候选的前后版本校验，不硬编码旧版本；记录 package、versionCode、证书指纹、APK SHA-256、设备、数据检查结果。
- Release 与 Compat 包分别验证；只有实际对应 APK 的覆盖升级成功报告才能标“保留数据升级”。
- 发布前验证提交 SHA、五个渠道、文件哈希、更新签名和 manifest；GitHub 发布后验证仅作二次检查。
- 服务器激活验证签名密码学有效性、公钥和 SHA，不接受只有字段存在的 manifest；失败不得切换 current。

## 验收

错误签名、错误 SHA、缺包、旧报告套新 APK、证书不符、versionCode 未递增全部非零退出；旧版本目录与回滚指针保持可用；所有校验测试通过。
